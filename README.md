## 📓 Diário de Bordo: Minha Jornada em QA

### 🗓️ Dia 1: O que é QA? (Fundamentos)
*   **O que aprendi:** Compreendi que o papel do QA (Quality Assurance) vai além de apenas "procurar bugs". O objetivo principal é garantir a qualidade do processo e do produto, prevenindo problemas antes mesmo que eles cheguem ao usuário final.
*   **Referências:** Conteúdo técnico focado na mentalidade de testes com base no especialista Julio de Lima.

### 🗓️ Dia 2: O Ciclo de Vida de um Bug
*   **O que aprendi:** Entendi o fluxo que um erro percorre no desenvolvimento de software:
    1. O QA identifica e reporta o problema (**Novo / Aberto**).
    2. O gestor avalia e atribui ao desenvolvedor (**Em Resolução**).
    3. O desenvolvedor corrige o código (**Corrigido**).
    4. O QA testa novamente para validar a correção (**Re-teste**).
    5. Se estiver tudo certo, o bug é finalmente **Fechado**.

### 🗓️ Dia 3 & 4: Metodologias Ágeis e Tipos de Teste
*   **Metodologias Ágeis (Scrum & Kanban):** Estudei como os times de tecnologia se organizam utilizando Sprints (ciclos curtos de trabalho), reuniões diárias (Daily) e quadros visuais para acompanhar o progresso das tarefas.
*   **Testes Funcionais:** Focados em validar o que o sistema faz (ex: testar se um botão de login realmente autentica o usuário).
*   **Testes de Regressão:** Focados em testar partes antigas do sistema após uma nova atualização, garantindo que o código novo não estragou o que já estava funcionando.
